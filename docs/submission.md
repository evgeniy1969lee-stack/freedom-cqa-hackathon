# Сдача результатов CQA · Нуфтяники

Формат взят из приложения к Student Guide. До стоп-кода в открытом репозитории команды должны быть `results/dev/results.json` с **65 записями** и `results/prod/results.json` с **10 записями**. Один исходный `conversation_id` соответствует одной записи, включая случаи ошибки. На контрольный прогон, проверку и push отведён один час.

## Получить файлы

1. Запустите локальный Go API и Python-сервис с Ollama по [README](../README.md). Сохраните полные JSON-ответы API организаторов с `data.records` вне репозитория. Для PROD используйте ссылку и группу, которые выдадут организаторы.
2. Откройте PowerShell в корне репозитория. Укажите адрес запущенного API и номер официального чек-листа. В проверенной локальной сборке адрес `http://127.0.0.1:18088`, версия 1 содержит исходные правила, а версия 2 добавляет секции. На чистой базе официальный чек-лист обычно имеет версию 1. Скрипт сравнит правила выбранной версии с исходными.
3. Подставьте пути к сохранённым файлам. Команды ставят по одному диалогу в очередь, используют подходящие уже завершённые оценки и сохраняют итоговый JSON.

~~~powershell
python -X utf8 scripts/submit_results.py dev 'C:/cqa-data/dev.json' --team-name 'Нуфтяники' --checklist-version 1 --api http://127.0.0.1:18088
python -X utf8 scripts/submit_results.py prod 'C:/cqa-data/prod.json' --team-name 'Нуфтяники' --checklist-version 1 --api http://127.0.0.1:18088 --deadline-minutes 50
~~~

Перед PROD приостановите DEV-скрипт через Ctrl+C и дождитесь окончания одного активного задания. После контроля повторите команду DEV для продолжения с сохранённых результатов. Флаг `--export-only` выгружает обработанный набор без нового запуска. Если время заканчивается, `--export-only --allow-unfinished` сохраняет незавершённые записи со статусом `error`. `--deadline-minutes 50` делает такую выгрузку по истечении 50 минут, чтобы оставить время на проверку и push. Если активное задание успеет завершиться, повторите экспорт.

Для фонового DEV-прогона укажите `--pause-file 'C:/cqa-data/pause-dev'`. Создание этого файла останавливает добавление новых заданий после текущего. Для продолжения удалите файл паузы и снова запустите команду DEV.

## Формат JSON 1.0

Корневой объект содержит `schema_version` со строкой `"1.0"`, `team_name` со строкой `"Нуфтяники"`, `model` с фактическим режимом и названием, а также массив `results`. Проверенная локальная конфигурация использует `{"mode":"local","name":"qwen3.5:2b"}`.

У записи со статусом `ok` ровно восемь объектов в `criteria`. В каждом есть `criterion_id`, `value`, краткое `rationale` и массив `evidence_turns`. Номера реплик считаются **с 1 по всему исходному массиву**, включая клиента, бота и системные события. Для пропущенного действия указывается проверенный участок. Значения сохраняются как JSON-булевы, `null` или целые числа.

| Код | Допустимое значение | Вес |
| --- | --- | ---: |
| `contact` | `true`, `false` | 10 |
| `discovery` | `true`, `false`, `null` | 15 |
| `identification` | `true`, `false`, `null` | 20 |
| `consultation` | `0`, `5`, `10`, `15`, `20`, `null` | 20 |
| `empathy` | `true`, `false` | 15 |
| `dialogue` | `0`, `4`, `7`, `10` | 15 |
| `closure` | `true`, `false`, `null` | 5 |
| `critical` | `true`, `false` | — |

В `score.final_score` записывается исходный автоматический итог от 0 до 100. Для шкал берётся доля от максимальной ступени, умноженная на вес. N/A исключается из знаменателя. Итог округляется до двух знаков. `score.critical_flag` совпадает с `critical.value` и учитывается отдельно. Выгрузка использует ответы и балл до апелляции.

Пример структуры одного успешного результата. Скрипт подставляет реальные ID, оценки и реплики из запуска модели.

~~~json
{
  "schema_version": "1.0",
  "team_name": "Нуфтяники",
  "model": {"mode": "local", "name": "qwen3.5:2b"},
  "results": [
    {
      "conversation_id": "demo-001",
      "status": "ok",
      "criteria": [
        {"criterion_id": "contact", "value": true, "rationale": "Оператор поздоровался и представился.", "evidence_turns": [4]},
        {"criterion_id": "discovery", "value": null, "rationale": "Вопрос сразу понятен.", "evidence_turns": [1]},
        {"criterion_id": "identification", "value": null, "rationale": "Общий вопрос.", "evidence_turns": [1]},
        {"criterion_id": "consultation", "value": 15, "rationale": "Один нюанс остался без ответа.", "evidence_turns": [5, 6]},
        {"criterion_id": "empathy", "value": true, "rationale": "Оператор признал неудобство.", "evidence_turns": [4, 5]},
        {"criterion_id": "dialogue", "value": 7, "rationale": "Оператор повторил шаг, диалог остался понятным.", "evidence_turns": [5, 6]},
        {"criterion_id": "closure", "value": true, "rationale": "Предложил помощь и попрощался.", "evidence_turns": [8]},
        {"criterion_id": "critical", "value": false, "rationale": "Грубых ошибок не выявлено.", "evidence_turns": [4, 5, 6, 8]}
      ],
      "score": {"final_score": 85.38, "critical_flag": false}
    }
  ]
}
~~~

Пример структуры для неудачной обработки. В реальном файле нужен исходный ID и фактическая причина.

~~~json
{
  "conversation_id": "demo-002",
  "status": "error",
  "criteria": [],
  "score": null,
  "error": "Не удалось получить ответ модели."
}
~~~

## Проверить и отправить

- Убедитесь, что экспорт завершился успешно, показал 65 DEV или 10 PROD записей и что все ошибки имеют понятную причину. Скрипт проверяет уникальные ID, неизменность транскриптов, версии, модель, восемь критериев, номера реплик и расчёт балла.
- Перед публикацией просмотрите обоснования, особенно для пяти звонков. Уберите из публичного JSON лишние персональные сведения. В Git добавляйте только проверенные файлы результатов, без исходных транскриптов, аудио, подписанных ссылок и SQLite.
- Сделайте commit и push в ветку, доступную организаторам по переданной ссылке. После push откройте ссылку на ветку и проверьте оба пути.

~~~powershell
git add -- results/dev/results.json results/prod/results.json
git commit -m "Submit CQA DEV and PROD results"
git push
~~~

Если DEV готов раньше, его можно отправить отдельным коммитом с одним путём. Структура обоих файлов одинакова, принадлежность к набору определяется папкой.
